CASE 02 · BCI · EEG

多模态 EEG 预处理管线

在 BCMI 实验室处理 10 个公开数据集、累计 380+ 小时的 EEG / ECG / EOG。 管线的价值不在滤波那几行，而在把「拿到数据先别跑」的判断规则写成了一个可复用的 skill： 先 QC，再人工决策，最后才预处理。

  • 角色独立开发
  • 场景BCMI 实验室 · OpenNeuro 公开数据
  • 规模10 个数据集 · 380+ 小时
  • 仓库EEG-preprocess-pipeline-skill ↗
工具负责执行和出证据，人负责判断哪些数据不该进管线。这条分工写进了流程，也写进了 skill。

01

问题：每个数据集都从同几个坑开始

公开 EEG 数据的麻烦很少在算法，而在进入算法之前：.vhdr 和 .set 有的存伏特、有的存微伏；原始信号的 std 常常是几千 µV， 但这不代表数据坏了；参考电极有时是记录通道，有时只是一个名字； 同一数据集里通道数还会从 63 变成 61、从 64 变成 256。

如果每换一个数据集都重新发现一遍，就会在无效预处理上浪费算力。 更糟的是把错误静默带进下游：线上模型不会告诉你，它学的是没换算单位的信号。

02

做法：先 QC，再预处理

阶段 A：QC 只体检，不动数据

先做单位换算，再逐通道算 mean / std / min / max，检查 NaN / Inf， 按阈值把通道分成 bad / noisy / normal，并为每个被试生成一张固定随机段的 10 秒 QC 图 —— 种子取自被试编号，所以同一份数据每次生成的图完全一样。 最后汇总成一份跨被试的 qc_report.txt，附排除建议。

QC 本身不滤波、不降采样、不归一化。 它只回答「这份数据现在长什么样」，不替人做决定。

阶段 B：预处理与合并

通道选择 → 带通滤波 → 陷波 → 降采样 → z-score，按被试写成 HDF5。 ECG 不存连续信号，切成 10 秒 epoch；EMG、GSR 这类通道直接丢弃。 合并时如果同一数据集的通道数不一致，就按通道数拆成多个 H5，不硬凑成一个。

skill 化的不是脚本，是判断规则

管线最终打包成一个 skill，核心是一份 SKILL.md： 单位换算的判定表、12 个数据集的参考电极处置、通道分类阈值、 HDF5 的目录结构、多通道数的合并策略，全部写成可执行的规则。 agent 读到规则再动手，同一批坑不需要在第二个数据集上再踩一次。

  • ds005114：63 通道（有 T7/T8）和 61 通道（无）分开合并，不强行对齐。
  • ds004118：64 通道和 256 通道分成两个 H5；E129 是记录到的参考通道，要丢。
  • ds005087：Cz 只是参考电极的名字，不在 63 个通道里，不能当通道删。

03

最容易错的地方

  • 所有通道 std 都接近 0 数据存的是伏特，没有换算。统一做 raw._data *= 1e6； 即使原本已经是 µV，放大后的量级也会被后面的 z-score 抹平。
  • 看到 std 两三千 µV 就想弃数据集 原始 µV 信号带 DC 偏移，std 在 2000–10000 µV 很常见。 先跑 0.3 Hz 高通，再判断滤波后的结果。
  • 把参考电极当成普通通道删掉 先查 _eeg.json 的 EEGReference， 再看这个名字是否真的在 raw.ch_names 里：在就丢，不在就不操作。
  • 不同被试通道数不一致 不要强行拼成一个 H5。按通道数分组，各自合并，下游按组读取。

04

结果

10个 OpenNeuro 数据集
380+小时多模态信号
3个阶段：QC / 预处理 / 合并
1个可复用的 skill

已处理的数据集包括 ds004118（驾驶）、ds004995（食物）、ds005087（视觉对象）、 ds005089（选择性注意）、ds005114（TBI）、ds005273（意识）、ds005795、 ds006018、ds006260 和 ds006434（听觉脑干）。每个数据集的参考电极和工频选择 都记在 SKILL.md 里，不靠记忆。

代码以 MIT 协议开源。换一台机器，只要改脚本顶部的 BASE 和 TASK 两个配置项，就能按同样的顺序重跑。

05

反思

这套管线真正可复用的部分不是代码，而是那张「每个数据集必须回答的问题」清单： 单位是什么、参考电极在不在通道里、通道数是否一致、哪些通道该丢。 脚本只是把这些答案落了地。

局限也清楚：QC 阈值是起点不是真理，遇到 TBI 或临床数据要把 BAD / NOISY 调到 1000 / 10000 µV；坏通道最终仍靠人看图判断。下一步我想做两件事： 一是让坏通道检测给出可复查的证据，而不只给一个标签； 二是用下游模型的效果反过来验证预处理选择，而不是只看图好不好看。

一句话：先让数据通过体检，再让它进入模型。
