脑机接口 · EEG

EEG 预处理的那些坑

批量处理十余个公开数据集(累计数百小时 EEG/EOG/ECG 数据)后沉淀的经验。 核心结论一句话:数据质量先行——先 QC 再预处理,不要拿到数据直接跑。 这些经验已沉淀为一个可复用的预处理 pipeline(见项目页)。

坑一:拿到数据就直接跑预处理

最贵的错误是预处理跑完几小时后,才发现数据本身有问题。正确顺序:

原始数据
  │
  ▼
[1. QC 质量检测] ── 统计评估 + 可复现随机段图像 + 跨被试汇总报告
  │
  ▼
[2. 用户决策] ──── 放弃数据集 / 排除被试 / 丢弃通道 / 调整参数
  │
  ▼
[3. 预处理] ────── 滤波 → 陷波 → 重采样 → z-score → HDF5
  │
  ▼
[4. Merge] ─────── 按通道数分 H5 合并

QC 阶段对每个被试做:单位转换、逐通道统计(mean/std/min/max)、通道分类(bad/noisy/normal)、NaN/Inf 检查、可复现随机段图像(用被试 ID 做种子)、跨被试质量汇总 + 排除建议。

两条原则:

  • QC 只看原始数据,不滤波、不降采样、不归一化——它评估的是数据本来的样子。
  • QC 阈值要按数据类型调。常规数据 bad 通道阈值 2 µV;临床数据(TBI 等)幅值大得多,阈值要调到 1000 µV 量级,否则全部误报。

坑二:单位转换——最关键也最易错的点

不同格式的数据文件存的单位不一样,处理错了,后面 QC 全是假的:

格式判断方法处理
BrainVision .vhdr元数据标 V无条件 ×1e6
EEGLAB .set(channels.tsv 写 uV)max(abs(data)) < 0.01×1e6(存的是 V)
EEGLAB .set(channels.tsv 写 uV)max(abs(data)) > 1不要 ×1e6(已存 µV)
EEGLAB .set(无 channels.tsv)无法判断直接 raw._data *= 1e6 最保险

推荐统一做法:所有数据一律 raw._data *= 1e6。即使已经是 µV 量级,再乘 1e6 变成百万级,但后面反正做 z-score,缩放不影响结果。这个技巧把"判断单位"这个易错步骤整个消掉了。

排查表:

  • QC 显示全部通道 BAD(std = 0)→ 数据是 Volts 但没 ×1e6
  • QC 显示全部通道 NOISY(std 几千 µV)→ 多半是正常的:原始数据含 DC 偏移,0.3 Hz 高通后即改善。不要因 QC 的 std 高就放弃数据集——先跑预处理看看滤波后效果

坑三:参考电极——在不在通道列表里,处理完全不同

不同数据集的参考电极五花八门(Cz、FCz、乳突、耳垂……),处理规则只有一条:

查 _eeg.json 的 EEGReference → 确认该通道是否在 raw.ch_names 中 → 在就丢弃,不在就不操作。

原因:有的数据集把参考电极作为真实记录通道存了下来(要丢弃),有的只是元数据里的名字,根本不在通道列表里(不能动,动了反而报错)。举例:

  • Cz 作为记录通道存在(如某些 63ch 数据集)→ 丢弃
  • Cz 只是参考名,不在 63ch 里 → 不操作
  • EGI 128ch 系统的 Cz (E129) 是真实通道 → 丢弃
  • 查不到参考信息 → 查 _eeg.json 的 EEGReference 字段

同类问题:EMG/GSR/CWL(脉冲校正)等非目标通道,统一建立丢弃清单,存在就丢。

坑四:同一数据集里通道数不一致

真实数据集里,不同被试/不同 session 的通道数可能不一样(电极掉了、系统升级)。合并成一个 H5 会导致张量形状对不齐,正确做法是按通道数分文件:

# 如某数据集: 63ch(有 T7,T8) vs 61ch(无 T7,T8)
dataset_63ch.h5  →  EEG=211seg
dataset_61ch.h5  →  EEG=6seg

# 又如: 64ch vs 256ch(高密度)
dataset_64ch.h5  →  EEG=99seg
dataset_256ch.h5 →  EEG=57seg

多模态的存储结构也要分别设计:EEG/EOG 按连续信号存,ECG 切成 10 秒 epoch 存(500 Hz × 10s = 5000 samples,HDF5 chunk 对齐 epoch 大小,读取时整块命中)。

QC 报告应该长什么样

QC 的产出不是给自己看的,是给"决策"用的。一份够用的报告要包含四块:

1. 总体统计
   Total subjects: 91
     OK: 12 / POOR: 79 / No data: 0

2. 排除建议(带原因)
   Recommended to exclude:
     sub-XXX: 24/62 bad channels (std < 2uV)
     sub-YYY: read error (ALLEEG format)

3. 通道问题(跨被试汇总)
   CPz: reference channel → will be dropped
   VEOG: flat in some sessions → will be checked

4. 整体评估
   Normal channels ratio: 82.3%
   Assessment: FAIR — some sessions may need exclusion.

QC 图像用被试 ID 做随机种子(如 sub-07 → 7),保证每次画出来的是同一段数据——QC 结论才能复现,两个人看的是同一张图。

总结:三条最值钱的经验

  1. 先 QC 再预处理——所有关于数据的决策,都应该建立在看过原始数据之后,而不是跑完 pipeline 之后。
  2. 把易错判断变成不变式——单位判断容易错,就统一 ×1e6 让它不再需要判断;参考电极规则收敛成一条"在就丢、不在就不动"。
  3. 数据形状问题用结构解决——通道数不一致不是 bug,是数据的真实形态,分文件存比硬合并诚实得多。
