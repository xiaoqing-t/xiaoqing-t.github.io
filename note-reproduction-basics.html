科研方法论

科研复现基本功

融合了三个来源:study-copy-understand-modify 学习循环、证据约束精读(nature-paper-card)、实验纪律(codex-autoresearch)。 适用场景:复现论文、读论文、做实验、沉淀知识。

核心心法

论文不是书,是"论证"——作者在论证"我的方法好"。你的任务是快速抓住论证结构,不是读完全部文字。

三条铁律:

  1. 证据约束——每个结论必须能溯源到论文某页/某图/某公式,不能凭空概括。
  2. 笔记自己写——AI 讲,你复述,AI 纠错。AI 不替你写笔记。
  3. 实验靠纪律——一次改一件事,可量化,可回滚,可信记录。

一、论文精读:三层阅读法

第一层:扫读(3 分钟)——建立整体感

  • 只读:标题、摘要、Figure 1(架构图)、图表标题
  • 回答三问:解决什么问题?方法核心是什么?效果多好?
  • 产出:一句话说出这篇论文在干嘛

第二层:读结构(30 分钟)——理解论证链

  • 引言:问题动机 + 现有方法不足
  • 方法:看架构图,顺着数据流走一遍(输入 → 各模块 → 输出)
  • 实验:只看主结果 + 消融(消融 = 证明每个组件都必要)
  • 产出:能画出流程框图,能说出每个模块作用
  • 遇到不懂的概念直接跳过,标记"这里有个不懂的,大概是干这个的",继续往下

第三层:抠细节(需要时才做)

  • 公式推导、超参数、实现细节、代码
  • 只有要复现或深究某点时才需要这层

贯穿三层:带着问题读,不被动读

  • 读方法前先问:"如果我是作者,我会怎么设计?"再看作者怎么做,差异即所学
  • 读实验前先问:"这个结果能支撑论点吗?"

二、论文精读卡(Paper Card,证据约束)

精读一篇论文时,产出固定 16 节的 Paper Card。每个实质性结论必须带来源指针 [Paper: PDF p.N / Figure N / Table N / Section]。无法溯源的内容写 Not assessable,不要编造。

节内容关键问题
01基本信息标题/作者/期刊/年份/DOI
02一句话总结用"为了__,做了__,实现__"结构
03研究问题作者要解决什么具体问题
04背景脉络该领域怎么发展到这(外部检索才可信)
05痛点现有方法的不足(数据病/方法病)
06核心思想一句话说清创新点
07方法概览数据流:输入 → 各模块 → 输出
08模块拆解每个模块的作用,为什么存在
09关键公式抄下来 + 解释每个符号
10实验证据链每个主张 → 哪个实验/数据支撑
11结论正确解读结果到底说明了什么(不过度解读)
12作者承认的局限作者自己说了哪些不足
13批判分析证据够不够?替代解释?
14学到的知识用自己的话写学到什么
15知识连接和已有知识/其他论文的关联
16可检验的想法基于此能做什么新实验

批判分析三问(第 13 节):

  1. 这个结果能支撑作者的论点吗?(证据强度)
  2. 有没有替代解释?(反例思维)
  3. 如果去掉某个组件会怎样?(消融思维)

三、概念攻坚:遇到不会的怎么办

读论文/复现遇到不懂的概念(如 VAE、Transformer、KL 散度):

  1. 识别层次:这是"地基概念"(需要彻底学)还是"外围细节"(知道在干嘛就行)?
    • 地基:方法的核心机制 → 开概念笔记,彻底学
    • 外围:实现细节/工具 → 扫一眼,需要时再回来
  2. AI 讲、你复述、AI 纠错:AI 用类比 + 上下文讲清概念,不急着写代码;你用自己的话写进概念笔记(强制,这是真正获取知识的唯一位置);AI 对照你的复述指出偏差。
  3. 检验标准:能讲清"为什么"(机制),不是"是什么"(结论)。写完后在进度文件加索引。

概念笔记模板:

# [概念名]
## 一句话解释(类比)
## 为什么在这篇论文里需要它
## 核心细节(公式、关键点,自己的话)
## 我的理解验证(假装讲给别人听)
## 卡住的地方 / 疑问

常见概念教学顺序:框架 → 改造 → 技巧(如 VAE → SVAE 频域改造 → 重参数化);先讲"要解决什么问题",再讲"怎么解决",最后讲"为什么这样解决"。

四、复现纪律:study-copy-understand-modify

目录铁律

项目/
├── 01_original/   # 原始材料(只读,权威来源)
│   ├── repo/      官方代码(记录 commit hash)
│   ├── paper/     论文 PDF、补充材料
│   └── data/      原始数据
├── 02_mine/        # 工作区(所有代码、实验)
│   ├── src/       你的代码
│   ├── experiments/ 实验记录
│   ├── logs/      运行日志
│   └── data/      处理后的数据
└── 03_notes/       # 学习笔记(第二个大脑)
    ├── 00_进度.md  进度/下一步/卡点
    ├── 01_paper.md 论文理解笔记
    ├── concepts/   概念笔记(一个概念一个文件)
    ├── code/       代码理解
    └── methods/    复现方法论
  • 01_original 只读——它是权威来源,永不污染
  • 02_mine 从抄开始,目标是自己的实现
  • 03_notes 是唯一跨会话的上下文——任何会话读 00_进度.md 就能接上

四步循环

  1. study:读懂代码(AI 逐段讲"这段为什么存在")
  2. copy:抄进 02_mine/src,每段加自己的注释
  3. understand:关掉官方代码,凭理解重建关键模块,卡住再看
  4. modify:改自己的实现,跑实验验证

五、实验纪律:可测量的自主实验

循环:看证据 → 改一件事 → 测量 → 改进则保留/失败则回滚 → 记录 → 重复直到达标

五条纪律:

  1. 一次只改一件事——指标变了才知道是谁的功劳。严禁顺手改别处。
  2. 必须可量化——不能"感觉变好",要有一个命令能测出一个数字。指标要确定性强、能比较。
  3. 失败就回滚——用 git 管理实验,每个 trial 一个 commit,坏的 revert。仓库永远保持"当前最优"。
  4. 信任记录不信记忆——实验历史写入文件(append-only),不靠"我记得上次改了啥"。失败就明确失败,不用"其实还行吧"自欺欺人。
  5. 困难 ≠ 阻塞——实验失败是"困难",继续试。只有缺数据/硬件/外部权限才是"阻塞"。

实验记录格式:

---
exp_id: {体系}-{设备}-YYMMDD-{序号}
date: YYYY-MM-DD
goal: 本次实验验证什么
---

## 假设
## 改动(只列一处!)
## 指标命令
## 结果(数字)
## 对比基线
## 结论:keep / revert
## 卡点

六、沉淀:summarize-as-skill

每个项目/每次学习循环的终点,把通用知识沉淀成可复用资产:

  • 概念 → 概念笔记(concepts/)+ 进度索引
  • 方法 → 复现方法论(methods/)
  • 可复用流程 → 沉淀成 skill
  • 通用经验 → 写进记忆(跨会话复用)

检验标准:下次遇到类似问题,能不能不用重新摸索。
